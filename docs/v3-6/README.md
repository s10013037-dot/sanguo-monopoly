# V3.6 呂布 GLB 美術樣板

本次只替換 `lvbu` 的立體美術及其展示操作。其餘七位角色的模型、材質與動畫生成程式未變；24 格棋盤、規則、武將能力與數值、存檔及 Pages 工作流程未變。呂布仍是原有可招募武將，沒有新增可選主公或改變招募機制。

## 實際交付

- 專屬曲面：梨形圓臉、分層紅棕眼睛、彎曲髮束與後腦分層髮流。
- 雙紅羽翎：弧形羽面、重疊羽片與細羽軸，替換原本的兩根彎管。
- 黑紅金盔甲：分層肩甲、胸甲與簡化獅面浮雕、護腕、紅寶腰扣、分片裙甲與立體金線。
- 方天畫戟：主槍刃、側月刃、內側小鉤、金色脊線、寶石接頭、握桿環與紅纓；固定在掌心關節。
- 厚披風：封閉雙層曲面、自然外擴、立體褶線、金色包邊與簡化背面紋章。
- 呂布專用展示台與補光、柔和陰影、正面／側面／背面預設、臉部特寫與更近的縮放。可拖曳 360 度旋轉，手機支援觸控。
- 保留原有待機、眨眼、勝利與旋轉登場，呂布展示新增原有走路動作的播放按鈕。所有動作仍由原本純視覺關節函式驅動，不觸發遊戲事件。

**結論：這是可操作、可匯入 Blender 的 GLB 美術原型，並未達到概念圖中的高級商用盲盒雕刻品質。** 未把檔案格式升級當作品質達標的依據。後續應由 3D 美術在 Blender 細雕髮流、獸面甲、羽枝與武器雕花，完成 UV、烘焙、手繪／PBR 貼圖及表情，再依下述關節介面匯回。

## GLB 評估與共用架構

開始時 main 沒有 GLB、glTF 或 Blender 專業角色資產，只有共用程式化工廠。本版不下載來源不明的模型，而是以自有訂製曲面建立原型，再真正匯出成 glTF 2.0 二進位資產；遊戲使用 Three.js 官方 `GLTFLoader` 載入它們。

- [低細節 GLB](../../src/assets/lubu-board.glb)：約 560 KiB，20,352 個三角形，60 個網格部件。
- [展示 GLB](../../src/assets/lubu-display.glb)：約 1,244 KiB，54,884 個三角形，60 個網格部件。
- 兩個 LOD 由同一份 [模型來源](../../src/three/lubuArt.ts) 產生，沒有兩套獨立美術設計；網格依材質與動畫關節合併，沒有為每片羽毛保留獨立 draw call。
- [載入與實例化](../../src/three/lubuAsset.ts) 只為呂布啟用。CPU 模板最多快取兩個 LOD；每次展示複製自身的幾何與材質，關閉時由原本資源管理器釋放。模板不直接提交給 GPU。
- 共用 `createCharacter(kit, 'lvbu')` 分派至同一模型；卡片頭像由低細節 GLB 實際渲染，展示依畫質載入對應 LOD。現有棋盤玩家是四位主公，因此本版不強行把呂布放成玩家棋子；未來如需在棋盤顯示呂布，可直接使用同一工廠。
- 資產 URL 經 Vite 打包，尊重 `/sanguo-monopoly/` 子路徑。模型載入失敗時明示使用同款訂製曲面備援，遊戲存檔與返回操作不受影響。

### 提供給後續 Blender 製作的介面

可直接匯入展示 GLB，保留角色根節點縮放及 `whole-figure → torso → head / left-arm / right-arm`、獨立 `left-leg / right-leg`、`left-eye / right-eye` 與 `cape` 節點。每隻手臂下保留 `palm-grip` 握點；武器節點以自訂屬性 `artRole: held-weapon` 標識。重複握點名稱在載入時可帶後綴。胸甲、髮束等靜態部件可替換為美術模型，不必重寫回合、存檔或 UI。

目前 GLB 交付的是節點關節模型，沒有假稱已含專業骨架或烘焙動畫。若改用骨骼模型，需另做節點或 AnimationMixer 適配，仍可限制在人物渲染層。

重建 GLB（Node.js 24）：

```bash
node --experimental-transform-types scripts/build-lubu-model.mjs
```

這個命令是資產製作工具，不是玩家遊玩或 GitHub Pages 部署的必要步驟；正式部署直接使用已提交的 GLB。

## 驗證與限制

驗證使用 `npm ci`、`npm test`、`npm run build`、`npm run test:e2e`。新增單元測試解碼兩份真實 GLB、檢查 LOD 預算與模型邊界，以及獨立資源、握持／動畫關節與護肩避讓；新增瀏覽器測試覆蓋呂布 GLB、四種動作、三視圖、手機觸控、反覆開關不改存檔與下載失敗備援。

桌面與手機尺寸的瀏覽器驗證使用 Chromium 軟體 WebGL；尚未驗證實體 Android／iPhone GPU 的幀率、發熱及所有機型。正式建置仍有 Three.js 共用 chunk 大於 500 KB 的提示，並非建置失敗。此版沒有專業美術資產、手工雕刻／貼圖或付費服務依賴。

### 最終驗證結果

- `npm ci`：成功，使用原有鎖定檔，沒有新增依賴。
- `npm test`：26 項通過（17 項原有規則、6 項原有人物、3 項新增 GLB／資源／護肩檢查）。
- `npm run build`：成功，包含兩份可載入 GLB。
- `npm run test:e2e`：18 項通過（原有 15 項與新增呂布 3 項）。
- 正式版真實截圖與子路徑資源驗證：5 張截圖，GLB／JS／CSS 全數 HTTP 200、無 JavaScript／console／requestfailed 錯誤、展示前後存檔相同；見 [驗證紀錄](screenshots/verification.json)。

重現正式版截圖：先 `npm run build`，再以 Node.js 24 執行 `node --experimental-transform-types scripts/review-lubu.mjs`，需有 Chromium 或以 `CHROMIUM_PATH` 指定。此工具僅在本機開啟正式產物，不會部署或修改 GitHub。

若日後由美術直接編輯 GLB，請將人工製作資產作為新的來源，**不要執行原型匯出腳本覆蓋人工成果**；並同步更新備援外觀與兩個 LOD。
